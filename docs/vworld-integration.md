# V-World(브이월드) 지도를 시뮬레이터에 넣기 — 조사 결과와 권장 구조

작성 2026-11-05. 공식 문서와 실측(타일 요청)으로 확인한 것은 그냥 쓰고, 확인하지 못한 것은 **추정** 이라고 표시했다.
인증키는 이 문서와 저장소 어디에도 적지 않는다 (`unreal/GyroSim/Config/vworld_key.txt` 는 git 제외).

---

## 0. 결론 먼저

1. **항공사진은 된다.** 형식이 표준 웹 메르카토르(EPSG:3857, 256 px, Google 타일 번호)라서 지금 쓰는 Cesium
   `CesiumUrlTemplateRasterOverlay` 에 URL만 바꿔 넣으면 붙는다. 실측 결과 키만 맞으면 Referer(도메인) 확인 없이
   데스크톱 프로그램에서 받아진다 (아래 4절).
2. **청주 공항(RKTU) 자체는 V-World 사진에 없다.** 공군 기지라 보안 처리로 **활주로·기지 약 4 × 4 km 가 가짜 숲으로 덮여**
   있다 (실측 그림 설명은 4절). 다른 군 비행장도 같을 것이다 (**추정**). 그래서 활주로는 지금처럼 시뮬레이터가 직접 그린
   활주로 메시를 써야 하고, 기지 주변은 V-World 숲 위에 활주로가 떠 있는 모양이 된다.
3. **지형(산 높이)과 3D 건물은 V-World 에서 가져올 공식 방법이 없다.** V-World 3D 데이터는 약관상 "공개제한 공간정보"이고
   자기 웹/데스크톱 뷰어 밖에서 꺼내 쓰는 길을 막아 두었다. 지형은 Cesium World Terrain(ion 토큰) 또는 무료 DEM 으로
   직접 만든 지형, 건물은 Cesium OSM Buildings 를 쓴다.
4. **"타일을 PC 에 영구 저장" 은 약관상 허락 없이는 안 된다.** 이용약관 19조 "오픈플랫폼에서 제공되는 데이터는 무단으로
   저장하지 못합니다", 18조 "제공하는 방법 이외의 다른 경로를 통해 ... 콘텐츠를 다운로드 받아서는 안됩니다".
   → 영구 캐시·전국 미리 받기는 **운영기관(공간정보산업진흥원)에 서면으로 허락을 받은 뒤에만** 켠다.
   그 전에는 서버가 허락한 3일짜리 HTTP 캐시(`Cache-Control: max-age=259200`, 실측)만 쓴다.
5. **전국을 날아다니며 실시간으로 받는 것은 호출 수로 보아 무리다.** 500 kt 저공이면 시간당 수만 장(**추정**) 이 필요하다.
   그래서 권장 구조는 "로컬 타일 프록시 + 캐시 우선 + 하루 예산 + 예산 끝나면 캐시/저해상도/Sentinel-2" 이다 (2절).

권장 순서: ① 로컬 프록시로 V-World 사진(온라인, 하루 예산 작게) → ② 진흥원에 저장·캐시 허락 문의 → ③ 허락되면 영구 캐시와
천천히 채우기 작업 켜기 → ④ 지형은 Cesium ion 토큰(지금 코드 그대로) 또는 Copernicus DEM 자체 지형 → ⑤ 건물은 OSM Buildings.

## 1. V-World 타일 서비스 사실 (공식 문서)

출처: WMTS 레퍼런스 https://www.vworld.kr/dev/v4dv_wmtsguide_s001.do , TMS 레퍼런스 https://www.vworld.kr/dev/v4dv_tmsguide_s001.do

| 항목 | 값 |
|---|---|
| URL (WMTS) | `https://api.vworld.kr/req/wmts/1.0.0/{key}/{layer}/{tileMatrix}/{tileRow}/{tileCol}.{tileType}` |
| 레이어 | `Base`(일반지도), `white`, `midnight`, `Hybrid`(사진 위 글자·도로, 투명 PNG), `Satellite`(항공사진) |
| 확장자 | Satellite = `jpeg`, 나머지 = `png` |
| 줌(레벨) | Base·Hybrid·Satellite 6~19, white·midnight 6~18. 실측: Satellite 20 은 오류 |
| 타일 번호 | "Google Index" — 행(row)은 북쪽이 0. 순서가 **z / 행(y) / 열(x)** 임에 주의 (보통의 z/x/y 아님) |
| 크기·투영 | 256 × 256, 웹 메르카토르 EPSG:3857 (실측 이미지 크기·위치로 확인) |
| TMS 판 | `.../req/tms/1.0.0/{key}/{layer}/{z}/{뒤집힌 행}/{열}` — 행만 남쪽이 0 |
| 범위 | 한국 영상만. 해외는 `Satellite/themes/...` 별도 도시 영상 |
| 오류 응답 | **HTTP 200 + XML** (`ExceptionReport`) 로 온다 (실측). 상태코드만 보면 안 되고 내용의 첫 바이트(JPEG `FF D8 FF`)를 봐야 한다 |
| 오류 종류 | `INVALID_KEY`, `UNAVAILABLE_KEY`(일시 사용 불가), `OVER_REQUEST_LIMIT`(일일 제한 초과), 등 (TMS 문서) |
| 캐시 헤더 | `Cache-Control: max-age=259200` (3 일, 실측) |

Cesium `CesiumUrlTemplateRasterOverlay` 에서 쓸 템플릿 (키 자리 표시만):
`https://api.vworld.kr/req/wmts/1.0.0/<KEY>/Satellite/{z}/{reverseY}/{x}.jpeg`
— 플러그인 헤더 설명대로 `{y}` 는 남쪽이 0, `{reverseY}` 가 북쪽 0 (= Google 행). 지금 Sentinel-2(EOX) 줄과 같은 방식.
단 이 URL 을 Unreal 속성에 직접 넣으면 키가 맵 파일(.umap)·로그에 남는다 → 2절의 로컬 프록시를 쓰면 키가 Unreal 에 안 들어간다.

### 키 · 도메인 · 호출 제한

- 키 신청 시 "인증키를 사용할 웹사이트의 도메인 및 하위 디렉토리" 를 적는다 (약관 15조). 데스크톱 프로그램이면 `localhost`
  또는 `http://localhost` 를 적으면 된다 (**추정** — 실측상 서버가 Referer 를 검사하지 않으므로 무엇을 적든 동작은 같았다).
- **실측: Referer 없음 / `http://localhost` / 엉뚱한 도메인 모두 같은 타일(200, 같은 바이트)이 왔다.** User-Agent 없이도 됨.
  → 현재 WMTS 는 도메인을 강제하지 않는다. 나중에 바뀔 수 있으니 프록시에 `Referer` 를 설정값으로 넣어 둔다.
  (Cesium 오버레이도 `RequestHeaders` 속성이 있어 헤더를 넣을 수 있다 — 플러그인 2.31 헤더에서 확인.)
- 키는 **개발키**(지금 받은 것)와 **운영키**(심사 후 발급) 두 가지 (약관 1·16조). 개발키는 신청하면 원칙적으로 바로 승낙,
  운영키는 개발키 만료 전에 온라인 신청 → 심사.
  - 유효기간: 운영기관이 정함 (약관 14조). 개발키 약 1 년, 운영키 약 2 년, 운영키로 바뀌어도 키 문자열·사용량은 그대로라는
    사례가 있다 (**추정**, 공식 문서 아님: https://github.com/developer-duno/naver-estate-web/pull/597 ).
  - 하루 호출 제한: 약관 13조 "모든 인증키에 대해 전송량 및 호출 회수를 제한 ... 운영기관에서 정하고 별도로 공지".
    **WMTS 의 정확한 숫자는 공개 페이지에서 찾지 못했다** (로그인 후 마이포털 > 인증키 관리에서 보일 것, **추정**).
    → 사용자 할 일: 마이포털에서 개발키의 일일 제한을 확인해 이 문서 3절 표에 적기. 그 전까지 예산은 보수적으로 잡는다.
  - 넘으면: `OVER_REQUEST_LIMIT` 로 그날 서비스 중단. 더 쓰려면 "서비스 용량 초과이용 신청"(목적·사유 기재).
  - 반복 위반·서버 방해는 키 해지 사유 (14조) — 그래서 프록시에 속도 제한·예산·오류 시 멈춤을 반드시 넣는다.

## 2. 권장 구조 — 로컬 타일 프록시 (전국 대응)

```
Unreal (Cesium) ──http://127.0.0.1:8765/vworld/sat/{z}/{reverseY}/{x}.jpg──▶ 로컬 프록시 (Python, 키는 여기만)
                                                                              ├─ 디스크 캐시 C:\GyroSimTiles\...
                                                                              ├─ 속도 제한 + 하루 예산
                                                                              └─ (예산·허락 범위 안에서만) api.vworld.kr
```

왜 프록시인가: Cesium 자체 캐시는 SQLite 4096 개 항목(`MaxCacheItems = 4096`, `CesiumRuntimeSettings.h`)에 서버 만료(3일)를
따르므로 "한 번 받으면 끝" 이 안 되고, Cesium 에는 하루 예산·오류 시 멈춤 기능이 없다. 그리고 키를 Unreal 속성에 넣지 않아도 된다.

### 프록시 규칙 (기본값, 모두 설정 파일로 바꿈)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 위치 | 127.0.0.1:8765 (바깥에서 접속 불가) | |
| 키 | `Config/vworld_key.txt` 에서 읽기. 로그에는 `<KEY>` 로 가림 | 공개 저장소 |
| 모드 | `online` / `cache-only`(오프라인: API 절대 호출 안 함) / `off` | 사용자 요구 |
| 캐시 | **허락 전**: 받은 날로부터 3일 지나면 삭제 (서버 헤더대로). **허락 후**: 만료 없음 | 약관 19조 |
| 캐시 위치 | `C:\GyroSimTiles\vworld\Satellite\{z}\{y}\{x}.jpg` (저장소 밖) | C: 여유 231 GB (Z: 294 GB 는 네트워크 드라이브로 보임 — 느림, **추정**) |
| 속도 | 초당 최대 4 요청(토큰 버킷), 동시 4 개 | Cesium 기본 동시 20 개는 너무 많음 |
| 하루 예산 | **2,000 요청/일** (한국 시간 0시 리셋), 한도 확인 후 한도의 20 % 이하로 조정 | 차단 방지 |
| 온라인 최대 줌 | 16 (그 위 17–19 는 캐시에 있을 때만) | 호출 수 4배씩 늘어남 |
| 미리 받기 | 끔 | 사용자 요구 |
| 오류 처리 | 응답이 JPEG 가 아니면 XML 을 읽어: `OVER_REQUEST_LIMIT`·`INVALID_KEY`·`UNAVAILABLE_KEY` → 그날 온라인 중지(cache-only 로 전환, HUD 에 표시). 그 밖의 오류·네트워크 실패·HTTP 429/5xx → 1, 2, 4 … 최대 300 초 쉬고 재시도, 같은 타일 3 번 실패면 그 타일은 24 시간 안 부름 | 200+XML 실측 |
| 빈 타일 | `FileNotFound`(바다 등) 는 "없음" 으로 기록해 다시 안 부름 | 낭비 방지 |
| 예산 끝·오프라인일 때 | ① 같은 타일 캐시 → ② 부모(낮은 줌) 타일 캐시를 잘라 확대해서 줌 → ③ 아무것도 없으면 404 (Cesium 이 그 자리를 낮은 해상도로 둠, **추정**) | 사용자 요구 |
| 한국 밖 / 줌 0–5 | V-World 를 부르지 않음. 0–5 는 Sentinel-2(EOX) 를 그대로 통과(이것은 기지가 안 보일 정도로 거칠다), 한국 밖은 Sentinel-2 또는 빈 바다색 | V-World 는 6–19, 한국만 |
| 기록 | `C:\GyroSimTiles\usage.jsonl` 에 날짜별 호출 수·오류 | 예산 확인 |

**구현됨 (11-05)**: `sim/vworld_proxy.py` (위 규칙 그대로, 단 포트는 **8790** — 8765 는 이 PC 의 다른 도구가 씀), `sim/server.py` 가 자동 시작,
Unreal `vworld` 땅 모드 (`sim_client.py`), 점검 `Scripts/vworld_check.py`. 사용법은 `unreal/README.md` "V-World 모드".
차이: 줌 0–5·한국 밖은 Sentinel-2 를 통과시키지 않고 **빈 타일** (14조 — 섞지 않기, 사용자 결정). Cesium 오버레이 최대 레벨 16, 화면 오차 4.
구현 시험에서 V-World 에 보낸 요청: **97 회** (타일 96 + 시간 초과 1, 시험용 하루 예산 95 — 동시 요청이 예산 검사를 2 회 넘김, 그 뒤 고침), 그 뒤 cache-only.

원래 계획 (위 구현의 근거):
- `build_level.py`: `CesiumUrlTemplateRasterOverlay` 하나 더 (`MaterialLayerKey` 새 이름, `template_url =
  "http://127.0.0.1:8765/vworld/sat/{z}/{reverseY}/{x}.jpg"`, `minimum_level=0`, `maximum_level=19`, `auto_activate=False`).
  최소 레벨을 6 으로 두면 Cesium 이 전 세계 4096 장부터 부르려 하므로(헤더의 경고) 0 부터 두고 프록시가 0–5 를 처리.
- `sim_client.py`: 지면 모드에 `vworld` 추가 (`cesium_token.txt` 에 `vworld` 줄). 프록시가 안 떠 있으면 `photo` 로 되돌림.
  화면 구석에 `지도: 브이월드(V-World), 국토교통부` 표시 (약관 13조, UrlTemplate 오버레이에는 출처 문구 속성이 없음).
- 지형이 있으면(ion 토큰) 같은 타일셋(Cesium World Terrain)에 오버레이로 붙이면 된다.

### 천천히 채우기 작업 (허락 받은 뒤에만 켬)

- `fill_cache.py`: 하루 예산 안(기본 1,500/일, 비행용 500 남김)에서 순서대로 받기, 중단 후 이어하기(이미 있는 파일은 건너뜀).
- 순서: 전국 z6→z14 → 주요 비행장 20 km 박스 z15–17 → 전국 z15 → 날아 본 곳 z16.
- 속도 초당 1–2 요청, 밤에만 돌게 해도 됨.

### 크기 · 기간 추정 (모두 **추정**: 한국 면적 약 10 만 km², 타일 평균 15 KB 가정 — 실측 타일은 9–10 KB 였지만 도시는 더 큼)

| 줌 | 타일 한 변 (위도 36.5°) | 전국 타일 수 (육지 위주) | 크기 | 누적 크기 |
|---|---|---|---|---|
| 6–12 | 500 km – 7.9 km | 약 2,300 | 0.04 GB | 0.04 GB |
| 13 | 3.9 km | 약 6,500 | 0.1 GB | 0.13 GB |
| 14 | 2.0 km | 약 26,000 | 0.4 GB | **0.5 GB** |
| 15 | 980 m | 약 10 만 | 1.6 GB | 2 GB |
| 16 | 490 m | 약 41 만 | 6 GB | 8 GB |
| 17 | 250 m | 약 165 만 | 25 GB | 33 GB |
| 18 | 120 m | 약 660 만 | 99 GB | 132 GB |
| 19 | 60 m | 약 2,600 만 | 395 GB | 527 GB |

해안 타일은 바다가 섞여 실제 수는 위 값의 1.3–1.5 배쯤 될 수 있다. 비행장 20 × 20 km 박스 하나: z15 460 장, z16 1,750 장,
z17 6,800 장(약 100 MB). → **C: 여유 231 GB 로 전국 z16 + 비행장 z17–18 까지 충분.** 전국 z18–19 는 비현실적.

기간 (하루 1,500 장): 전국 z6–z14 약 3–5 주, 비행장 10 곳 z15–17 약 6 주, 전국 z15 약 2–3 달.
하루 예산을 늘리려면 진흥원에 "초과이용 신청" (13조).

### 비행 중 호출 수 추정 (**추정**, 계산식 근거)

Cesium 은 화면에서 가까운 곳일수록 높은 줌을 부른다. 한 줌 레벨당 앞쪽 테두리를 약 12 장 폭으로 보고, 초당 새 타일 수
≈ 12 × 속도 / 타일 한 변 을 줌마다 더하면:

| 상황 | 가장 높은 줌 | 초당 새 타일 | 시간당 |
|---|---|---|---|
| 500 kt (257 m/s), 저공 300 m | 17 | 약 25 | 약 9 만 |
| 500 kt, 3,000 m | 15–16 | 약 10 | 약 3.5 만 |
| 300 kt (154 m/s), 3,000 m | 15–16 | 약 6 | 약 2 만 |
| 같은 곳 다시 비행 (캐시 있음) | — | 0 | 0 |

선회·고개 돌리기(VR)는 더 늘린다. → 하루 2,000 장 예산이면 **처음 가는 곳은 몇 분이면 예산이 끝난다.**
그래서 "캐시 우선 + 온라인 최대 줌 16 + 예산 끝나면 낮은 줌 확대" 가 필수. 허락을 못 받으면(3일 캐시만) 전국 비행은
결국 Sentinel-2(10 m) 가 기본이고 V-World 는 자주 나는 지역만 고해상도가 된다.

## 5. 지형 (전국)

V-World 는 외부 엔진용 지형 타일 API 를 공개하지 않는다 (레퍼런스 목록 https://www.vworld.kr/dev/v4apiRefer.do 에 2D 타일·WMS/WFS·
데이터·3D 웹/데스크톱 뷰어 API 만 있음). 3D 뷰어 내부 지형을 꺼내 쓰는 것은 약관 14·18조에 걸린다.

| 방법 | 장점 | 단점 | 크기 |
|---|---|---|---|
| **A. Cesium World Terrain (ion 토큰)** — 지금 `terrain` 모드 그대로 | 코드 이미 있음, 전 세계, 스트리밍 | 무료(Community) 요금제의 월 사용량 제한 있음 (**추정**), 인터넷 필요 | Cesium 캐시만 |
| **B. Copernicus DEM GLO-30 으로 자체 지형** | 무료(출처 표시), 오프라인, 키 없음 | 만드는 작업 필요 (GeoTIFF → quantized-mesh, 예: cesium-terrain-builder), 30 m 해상도 | 원본 한국 약 50 개 1°타일 ≈ 1 GB, 만든 지형 z0–14 약 1–3 GB (**추정**) |
| C. 국토지리정보원 5 m DEM (국토정보플랫폼) | 가장 정확 | 신청 필요, 라이선스 확인 필요, 크기 수십 GB (**추정**) | |

권장: 지금은 **A** (토큰만 넣으면 됨). 오프라인이 필요해지면 **B** — 만든 지형을 같은 로컬 프록시가 `layer.json` 로 서비스하고
`Cesium3DTileset` 의 URL 로 지정 (Cesium for Unreal 2.31 은 quantized-mesh `layer.json` 을 읽음, `Cesium3DTileset.h` 에서 확인).
한국 밖은 지형 없이 타원체(지금처럼 평평한 바다 높이).

  금지한다. → **Unreal 로 가져오는 공식 길 없음.** (진흥원 승낙을 받으면 가능할 수도 있음, **추정**)
- 권장: **Cesium OSM Buildings** (ion 자산 96188, 토큰 필요, 전 세계 스트리밍, OSM ODbL 출처 표시). 한국 도시는 건물 윤곽이
  꽤 있으나 높이는 대충(층수 없으면 기본 높이) (**추정**).
- 나중 선택: V-World "공간정보 다운로드" 의 2D 건물 윤곽 + 층수(예: GIS건물통합정보, SHP) 를 받아 높이로 밀어 올려 3D Tiles 로 만들기
  (개별 라이선스가 표시된 다운로드 자료는 그 라이선스를 따름 — 19조 단서). 데이터셋 이름·라이선스는 **확인 필요**.
  RKTU 기지 안 건물은 이런 데이터에도 없을 것 (**추정**).
- Google 사실적 3D 타일(`photoreal`)은 한국 대부분이 비어 있을 것 (**추정**, 지도 반출 제한).

## 7. 위험 정리

1. 기지 가림: RKTU·군 비행장 주변은 V-World 가 숲으로 덮음 → 활주로 메시와 어긋나 보임. 피할 수 없음.
2. 저장 금지: 허락 전 영구 캐시는 약관 위반. 허락 전에는 3 일 캐시만.
3. 키 차단: 일일 한도 미확인. 프록시 예산·오류 시 중지로 막음. 실측에서 오류가 200 으로 오므로 Cesium 직접 연결은 실패를 못 알아챔.
4. 키 노출: 공개 저장소. 키는 `vworld_key.txt`(git 제외)와 프록시 메모리에만. Unreal 속성·맵 파일·로그·문서에 넣지 않음.
5. 군사시설 조항(14조): V-World 와 기지가 보이는 다른 사진을 섞는 것은 해석에 따라 해지 사유 (**추정**).
6. 타일·파생물(합친 그림 등)을 GitHub 에 올리지 않음 (19조, 측량성과 국외 반출).
7. 개발키 만료 후 서비스 중지 → 만료 전에 운영키 신청.
